# Create IXApp React.js Frontend with a D365 Finance & Operations–Style Architecture
https://github.com/Omar-Qaid/IAX
You are a Senior React.js Architect, TypeScript Developer, Material UI Engineer, Enterprise UX Architect, and Microsoft Dynamics 365 Finance & Operations Solution Architect.

Create a completely new frontend project named:

```text
IXApp
```

The project will connect later to an existing ASP.NET Core REST Web API, but the current task focuses exclusively on creating the React.js frontend architecture, application shell, reusable components, page patterns, folder structure, routing, theme, and representative sample pages.

The frontend must be inspired by Microsoft Dynamics 365 Finance & Operations UI architecture and enterprise design patterns.

Do not copy Microsoft proprietary source code, branding, icons, or exact visual design. Implement similar enterprise concepts using React.js and Material UI.

# 2. Project Creation

Create the project with the name:

```text
IXApp
```

The expected project root should be:

```text
IXApp/
```

Initialize the project using Vite with React and TypeScript.

Example:

```bash
npm create vite@latest IXApp -- --template react-ts
cd IXApp
npm install
```

Install and configure all required dependencies.

After generating the project, verify that the following commands succeed:

```bash
npm run dev
npm run build
npm run lint
npm run test
```

# 3. Main Objective

Build a reusable enterprise frontend architecture that follows concepts similar to Microsoft Dynamics 365 Finance & Operations.

The application must provide:

```text
Application shell
Module navigation
Collapsible navigation drawer
Top application bar
Breadcrumbs
Company selector
Global search placeholder
User profile menu
Notification center placeholder
Page headers
D365-style action panes
Reusable page patterns
Reusable forms
Reusable fields
Reusable data grids
Reusable dialogs
Reusable lookup controls
FastTabs
Role and permission guards
Loading states
Error states
Empty states
Localization
LTR and RTL support
Light and dark themes
Responsive enterprise layouts
```

The architecture must support future business modules such as:

```text
Accounts Receivable
Accounts Payable
General Ledger
Inventory Management
Sales and Marketing
Procurement and Sourcing
Cash and Bank Management
Fixed Assets
Human Resources
System Administration
```

Initially, implement representative pages for:

```text
Dashboard
Customers
Customer Groups
Sales Orders
Currencies
Application Settings
```

Use mock data and mock services until the ASP.NET Core API is connected.

---

# 4. Architecture Principles

Apply the following principles:

```text
Feature-based modular architecture
Clear separation of responsibilities
Composition over duplication
Configuration over hardcoded page implementations
Strong TypeScript typing
Reusable page-pattern components
Reusable enterprise controls
Centralized API handling
Centralized error handling
Centralized notifications
Centralized permissions
Centralized route configuration
Centralized theme configuration
Centralized localization
Small focused components
Predictable state ownership
Lazy-loaded modules
No circular dependencies
No oversized components
No direct API calls inside visual components
```

Shared components must not contain module-specific business logic.

Business modules must depend on shared and core layers.

The core and shared layers must never depend on business modules.

# 6. Dependency Direction Rules

Enforce the following dependency direction:

```text
app
↓
modules
↓
patterns
↓
shared
↓
core
```

The permitted dependencies are:

```text
app → modules, patterns, shared, core
modules → patterns, shared, core
patterns → shared, core
shared → core
core → external libraries only
```

The following dependencies are forbidden:

```text
core → shared
core → patterns
core → modules
shared → patterns
shared → modules
patterns → modules
one business module → another business module directly
```

When one module needs information from another module, use a shared contract, API service, or application-level orchestration.

# Basic D365 F&O inventory gap analysis

**Scope:** Inventory master setup and the core transaction path in `IXApi/src/Modules/Finance`, as inspected on 2026-11-01. Reports, advanced warehouse management, production, planning, variants, and optional extensions are excluded. This is a source-code assessment, not a live SQL Server certification.

## End-to-end map

1. **Master setup:** Shared `EcoResProduct` and company `InventTable` exist. Release/configuration connects item group, item model group, storage and tracking dimension groups, units and default order settings. Site, warehouse, posting profile, journal name and number-sequence services exist. The setup readiness check now accepts company-chosen IDs instead of requiring sample IDs. D365 likewise releases products to legal entities and uses dimension groups and item model groups to govern transactions. [Microsoft product setup](https://learn.microsoft.com/en-us/dynamics365/supply-chain/pim/tasks/complete-basic-setup-released-product-master).
2. **Inbound:** Purchase order demand creates an inventory origin and ordered receipt. Product receipt physically receives it; vendor invoice financially updates it and on-hand value. Vendor returns have separate physical and financial paths. Source: `AccountsPayable/ProductReceipt/Services/ProductReceiptService.cs`, `AccountsPayable/Invoice/Services/VendorInvoiceService.cs`, `AccountsPayable/Return/Services/PurchReturnService.cs`. D365 distinguishes physical receipt from financial invoice. [Microsoft physical and financial updates](https://learn.microsoft.com/en-us/dynamics365/supply-chain/cost-management/physical-financial-updates).
3. **Stock and outbound:** `InventTrans`/`InventTransOrigin` carry transaction state, `InventSum` on-hand. Sales demand, reservation, picking, packing slip and invoice are implemented as separate steps. Source: `Inventory/Reservation/Services/InventoryReservationService.Picking.cs`, `AccountsReceivable/PackingSlip/Services/PackingSlipJournalService.cs`. D365 reservation protects stock for a sales order. [Microsoft reservation](https://learn.microsoft.com/en-us/dynamics365/supply-chain/inventory/reserve-inventory-quantities).
4. **Internal movement:** Movement, adjustment, transfer and counting journals have create/line/post paths. Transfer orders have create, ship and receive paths and transit dimensions. Source: `Inventory/InventJournal/Controllers/InventJournalController.cs`, `Inventory/Transfer/Services/InventTransferOrderService.cs`. D365 distinguishes immediate transfer journals from transfer orders with transit. [Microsoft journals](https://learn.microsoft.com/en-us/dynamics365/supply-chain/inventory/inventory-journals), [inventory posting](https://learn.microsoft.com/en-us/dynamics365/finance/general-ledger/inventory-posting).
5. **Costing:** FIFO, LIFO and weighted average settlement, recalculation, close and cancellation exist. [Microsoft inventory close](https://learn.microsoft.com/en-us/dynamics365/supply-chain/cost-management/inventory-close).

**Costing correction:** Journal issues, transfer orders, sales packing slips, and sales invoices now estimate cost from the financially tracked site pool, including all warehouses at that site. The basic item model group excludes physical value from cost. This follows Microsoft's [running average formula](https://learn.microsoft.com/en-us/dynamics365/supply-chain/cost-management/running-average-cost-price) and [financial dimension rule](https://learn.microsoft.com/en-us/dynamics365/supply-chain/cost-management/track-running-average-cost-per-inventory-dimension).

Positive movement and adjustment journals now take a missing line cost from the released item's inventory cost price. The user can still specify the line cost. [Microsoft inventory adjustment guidance](https://learn.microsoft.com/en-us/dynamics365/supply-chain/inventory/tasks/adjust-stock-levels-warehouse-basic-warehousing).

## Corrections and boundaries

- **Picking is present.** `InventoryReservationService.Picking.cs` changes `StatusIssue` to/from `Picked` and updates `InventSum.Picked`; packing-slip posting consumes picked rows. The existing `Inventory/GAPS.md` statement that `Picked` is never written is stale. Arrival/registration remains unverified and should be assessed only if that inbound process is required.
- **Batch/serial is a conditional gap, not a blanket requirement** for an untracked item. Location and advanced warehouse dimensions are intentionally outside this assessment.
- **More costing models do not automatically outrank the working FIFO path.** Standard cost and moving average require their own accounting rules; no approximation is recommended.
- **Not assessed:** UI usability, authorization by role, live SQL Server behavior, and every Finance feature outside the inventory-driven cycle. The older `README.md` and architecture review include dated claims contradicted by newer code; this assessment uses current source for status.

## Suggested implementation order

Resolve the FIFO readiness contradiction; verify the basic FIFO path end to end on SQL Server; implement Inventory period access; enforce purchase lifecycle state; then select any additional tracking or cost model based on the actual item master required. Keep each transaction path tied to `InventTrans`, `InventSum`, the source document and the shared posting engine.
